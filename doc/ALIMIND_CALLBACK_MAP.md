# 1. Назначение документа

Документ фиксирует карту `callback_data` Telegram-бота AliMind.

Цель:

- убрать путаницу в навигации
- разделить типы переходов
- зафиксировать текущие живые callback
- подготовить систему к дальнейшей чистке без ломки маршрутов

Этот документ нужен для того, чтобы любой следующий шаг по кнопкам делался осознанно.

---

# 2. Главный принцип

В AliMind callback должны делиться по смыслу.

Не все кнопки одинаковые.

Есть три типа переходов:

1. верхние справочные разделы
2. каталожные разделы
3. сервисные / бизнес-разделы

# 4. Текущая проблема системы callback

Сейчас callback живут в смешанном виде.

В проекте одновременно используются:

- отдельные callback для событий
- `catopen:*` для каталога
- старые сервисные callback
- callback, которые логически уже не должны быть категориями

Это создаёт путаницу.

Примеры архитектурной проблемы:

- `migration` технически живёт как категория, но логически это отдельный раздел
- `transport` технически живёт как категория, но логически это отдельный раздел
- `gov` и `emergency` частично смешивают объекты и справку

# 5. Текущая безопасная рабочая карта

На данном этапе безопасно использовать следующую структуру верхнего меню без ломки маршрутов:

## Справочное ядро

- `city_today` → События города
- `emergency_contacts` → Важные службы города
- `catopen:migration` → ВНЖ
- `catopen:transport` → Транспорт

## Каталожные разделы

- `catopen:trn` → Услуги переводчика
- `catopen:beauty` → Салон красоты
- `catopen:cafe` → Кафе и рестораны
- `catopen:taxi` → Такси
- `catopen:sport` → Спорт
- `catopen:fun` → Досуг

## Сервисные разделы

- `partner:open` → Стать партнёром AliMind
- `bizbot:open` → Бот для бизнеса

# 6. Новая целевая схема callback (на будущее)

После чистки проекта callback желательно разделить по префиксам.

## 6.1 Верхние разделы

Префикс:
`section:`

Примеры:
- `section:city_events`
- `section:city_services`
- `section:migration_info`
- `section:transport_info`

Назначение:
самостоятельные верхние разделы

---

## 6.2 Каталоги

Префикс:
`catopen:`

Примеры:
- `catopen:trn`
- `catopen:beauty`
- `catopen:cafe`
- `catopen:taxi`
- `catopen:sport`
- `catopen:fun`

Назначение:
открытие списков карточек

---

## 6.3 Сервисы

Префикс:
`service:`

Примеры:
- `service:partner_apply`
- `service:bizbot`

Назначение:
служебные и бизнес-модули

---

# 7. Правила для callback

## 7.1 Один смысл — один префикс

Нельзя смешивать:
- верхние разделы
- карточные каталоги
- сервисные модули

---

## 7.2 Верхние разделы не должны притворяться категориями

Разделы:
- ВНЖ
- Транспорт
- Важные службы города
- События города

Не должны в будущем жить как обычные карточные категории.





По строке callback должно быть понятно:

- это раздел?
- это каталог?
- это служебная кнопка?
- это пагинация?
- это карточка?

---

## 7.4 Не плодить новые префиксы без причины

Все новые кнопки должны встраиваться в уже утверждённую систему.

---

# 8. Приоритет внедрения

## Этап 1
Не ломать текущие маршруты.

Использовать:
- `city_today`
- `emergency_contacts`
- `catopen:*`
- `partner:open`
- `bizbot:open`

---

## Этап 2
Очистить главное меню и смысл кнопок.

---

## Этап 3
Только после этого переводить систему на:
- `section:*`
- `service:*`

---

# 9. Итог

Текущая рабочая схема callback в AliMind пригодна для безопасной перестройки интерфейса.

Главное правило:

Начала меняем структуру меню,
потом чистим naming callback,
а не наоборот.

---

# 10. Базовый вывод

AliMind должен прийти к системе, где:

- верхние разделы живут отдельно
- каталог карточек живёт отдельно
- сервисные модули живут отдельно

Именно это убирает клубок.

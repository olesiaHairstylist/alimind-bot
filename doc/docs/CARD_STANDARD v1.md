CARD STANDARD v1

Status: BASELINE DATA STANDARD
Purpose: Единый стандарт карточек объектов для бота, сайта, поиска и будущих AI-функций.

1. Смысл стандарта

Карточка объекта должна быть не “сообщением для Telegram”, а универсальным контент-объектом.

Один объект должен уметь жить сразу в нескольких средах:

Telegram-бот

сайт

внутренний поиск

AI-ответы

SEO-страницы

Это значит:

одна карточка = один источник истины

2. Главный принцип

Нельзя смешивать:

данные объекта

интерфейс Telegram

логику кнопок

способ показа на сайте

Карточка хранит сущность объекта.
Бот и сайт уже сами решают, как её показать.

3. Каркас карточки

Каждая карточка должна состоять из следующих блоков:

Идентичность

Классификация

Локация

Описание

Услуги / особенности

Контакты

Медиа

Служебные признаки

Метаданные публикации

4. Обязательные поля
4.1 Идентичность
"id"
"slug"
"name"

Назначение:

id — внутренний уникальный идентификатор

slug — человекочитаемый идентификатор для сайта и URL

name — основное имя объекта

4.2 Классификация
"category"
"type"
"status"

Назначение:

category — категория каталога

type — тип объекта внутри категории

status — статус объекта в системе

4.3 Базовое описание
"headline"
"short_description"
"full_description"

Назначение:

headline — краткая смысловая строка для сайта и карточек

short_description — короткое описание для списков

full_description — полное описание для страницы и полной карточки

4.4 Локация
"location"

Внутри:

"district"
"city"
"country"
"address_line"

Назначение:

район

город

страна

точная строка адреса, если есть

4.5 Контакты
"contacts"

Внутри:

"phone"
"whatsapp"
"telegram"
"instagram"
"website"

Назначение:

хранить способы связи как данные, а не как кусок текста.

4.6 Услуги / особенности
"services"
"languages"

Назначение:

services — список услуг, направлений или особенностей

languages — языки общения

4.7 Медиа
"media"

Внутри:

"cover_image"
"gallery"

Назначение:

одна главная обложка

дополнительные изображения

4.8 Функциональные признаки
"features"

Внутри, например:

"accept_requests"

Назначение:

хранить поведенческие возможности объекта, но не интерфейсные callback.

4.9 Публикационные метаданные
"is_published"
"updated_at"

Назначение:

объект опубликован или нет

когда последний раз обновлялся

5. Рекомендуемые значения
5.1 status

Нужно закрепить ограниченный набор значений.

Допустимый минимум:

partner

free

draft

archived

5.2 category

Нужно использовать единый словарь категорий.

Примеры:

beauty

sport

cafe

taxi

medicine

real_estate

6. Что не должно входить в каноническую карточку

Нельзя помещать в базовую карточку то, что относится только к Telegram UI.

Не включать:

callback

Telegram-specific button config

готовые inline-кнопки

markdown/html-разметку для Telegram

текст, завязанный только на одно представление

7. Правильная логика действий

Карточка не должна говорить боту:

“вот моя кнопка и вот мой callback”

Правильно так:

карточка хранит:

"features": {
  "accept_requests": true
}

А уже бот решает:

показать кнопку или нет

какой callback построить

куда вести пользователя

Это разделяет:

данные и интерфейс

10. Минимальные правила заполнения
Правило 1

Один JSON = один реальный объект

Правило 2

Поля должны хранить данные, а не куски интерфейса.

Правило 3

Краткое и полное описание не смешивать.

Правило 4

Локацию не держать одной неразделённой строкой, если можно разложить.

Правило 5

Контакты хранить отдельно по типам.

Правило 6

Медиа готовить с расчётом на сайт, а не только на бот.

Правило 7

Все новые карточки делать сразу по этому стандарту.

11. Что делать со старыми карточками

Старые JSON-карточки не обязательно ломать сразу.

Правильный подход:

принять CARD STANDARD v1

все новые карточки делать только по нему

старые переводить постепенно

на ревизии отмечать, какие карточки:

legacy

transitional

compliant

12. Статусы совместимости карточек

Для внутренней ревизии можно использовать такие оценки:

LEGACY — старая бот-ориентированная карточка

TRANSITIONAL — частично соответствует новому стандарту

COMPLIANT — полностью соответствует CARD STANDARD v1

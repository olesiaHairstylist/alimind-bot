Status: CORE INTELLIGENCE LAYER
Purpose: Превратить объекты, связи и районы AliMind в систему, которая умеет отвечать на реальные городские запросы пользователя.

1. Главная идея

Если:

CITY OBJECT MODEL описывает, что существует в городе

CITY GRAPH ENGINE описывает, как это связано

DISTRICT MODEL описывает, где это находится

то CITY QUERY ENGINE отвечает на вопрос:

как из этого получать точные ответы для человека

Именно здесь AliMind перестаёт быть просто каталогом и становится городским оператором запросов.

2. Что такое QUERY ENGINE

Это слой, который принимает запрос пользователя и превращает его в понятное системное действие.

Пользователь пишет:

“тренер по боксу в Махмутларе”

“дежурная аптека сегодня”

“такси в Кестеле”

“мастер по волосам рядом”

“партнёры beauty в Оба”

Query Engine должен:

понять смысл запроса

выделить сущности

найти нужные объекты и связи

вернуть релевантный результат

3. Базовая формула
USER QUERY
   ↓
QUERY PARSER
   ↓
INTENT + ENTITIES
   ↓

   ↓
RESULT SET
   ↓
BOT / SITE / AI RESPONSE
4. Из чего состоит CITY QUERY ENGINE

Я бы зафиксировал 5 основных слоёв:

1. Query Input Layer

Приём текста пользователя

2. Query Parser

Разбор запроса на смысловые элементы

3. Intent Layer

Определение, что именно хочет пользователь

4. Entity Resolver

Поиск районов, услуг, объектов, категорий

5. Query Executor

Запуск нужного запроса по данным/графу

5. Query Input Layer

Это самый верх.

Система получает:

текст в Telegram

поисковую строку на сайте

вопрос в AI-чате

Примеры:

“бокс махмутлар”

“где сделать стрижку”

“аптека сегодня”

“кто переводит документы”

“кафе в центре”

На этом этапе система ещё ничего не знает.
Она просто принимает сырой ввод.

6. Query Parser

Это первый реальный интеллект системы.

Его задача — разбить запрос на части.

Например запрос:

тренер по боксу в махмутларе

Парсер должен увидеть:

возможная услуга: бокс

возможный тип объекта: тренер / person

возможный район: Махмутлар

Или запрос:

дежурная аптека сегодня

Парсер должен увидеть:

intent: событие

category: pharmacy

date: today

8. Intent Layer

Это сердце Query Engine.

Система должна понять не только слова, но и тип запроса.

Базовые intents v1
find_objects

Найти объекты

Примеры:

тренер по боксу в Махмутларе

кафе в Оба

такси в Кестеле

find_service_providers

Найти, кто оказывает услугу

Примеры:

кто делает окрашивание

кто переводит документы

кто тренирует бокс

find_by_district

Найти объекты в районе

Примеры:

что есть в Махмутларе

партнёры в Кестеле

beauty в Оба

find_event

Найти событие

Примеры:

дежурная аптека сегодня

отключение воды

отключение электричества

open_known_object

Открыть уже известный объект

Примеры:

Olesya

Farid

Tiger Gym

browse_category

Открыть категорию

Примеры:

спорт

кафе

транспорт

9. Entity Resolver

После того как intent понятен, система должна связать слова пользователя с реальными сущностями AliMind.

Например пользователь пишет:

махмутлар

Resolver должен понять:

DISTRICT_MAHMUTLAR

Пользователь пишет:

бокс

Resolver должен понять:

SERVICE_BOXING_TRAINING

Пользователь пишет:

тренер

Resolver должен понять:

object_type = person

profession = coach

То есть это слой сопоставления языка пользователя с объектами системы.

10. Query Executor

Это слой, который уже выполняет запрос.

Пример 1

Запрос:

“тренер по боксу в Махмутларе”

После разбора:

intent = find_service_providers

service = SERVICE_BOXING_TRAINING

district = DISTRICT_MAHMUTLAR

Выполнение:

найти всех providers of boxing

отфильтровать по district mahmutlar

отсортировать

вернуть карточки

Пример 2

Запрос:

“дежурная аптека сегодня”

После разбора:

intent = find_event

event_type = pharmacy duty

date = today

Выполнение:

найти событие на сегодня

взять связанные объекты

показать их

Пример 3

Запрос:

“что есть в Кестеле”

После разбора:

intent = find_by_district

district = DISTRICT_KESTEL

Выполнение:

найти все объекты, связанные с районом

сгруппировать:

beauty

sport

taxi

cafe

отдать список или меню

12. Как Query Engine связан с поиском

Важно: поиск и query engine — не одно и то же.

Search

ищет совпадения

Query Engine

выполняет структурные запросы

То есть:

search нужен для “найди по слову”

query engine нужен для “ответь по смыслу”

Правильная зрелая схема:

search = primitive retrieval
query engine = semantic city navigation
13. Как Query Engine связан с AI

AI не должен отвечать сразу из головы.

Правильная цепочка такая:

user asks
   ↓
query engine interprets
   ↓
objects + relations found
   ↓
AI formats response

То есть AI — не источник фактов.
Источник фактов — City Query Engine + data layer.

Это суперважно.

14. Что это даст Telegram-боту

Бот сможет принимать естественные запросы, а не только кнопки.

Например:

“бокс в махмутларе”

“мастер по волосам”

“аптека сегодня”

“кафе центр”

И отвечать не тупо поиском по строке, а нормальным пониманием структуры запроса.

15. Что это даст сайту

На сайте появится:

нормальный поиск

фильтры по району

фильтры по услуге

страницы категорий

страницы районов

страницы “кто оказывает услугу”

То есть сайт будет не статичным, а навигационным.

16. Что это даст AI-ассистенту

AI сможет отвечать так:

Вопрос:

“Есть ли в Махмутларе тренер по боксу?”

Query Engine найдёт:

SERVICE_BOXING_TRAINING

DISTRICT_MAHMUTLAR

PERSON_FARID

AI ответит:

Да, в Махмутларе есть персональный тренер по боксу — Coach Farid.

Это уже очень другой уровень доверия.

17. Минимальный Query Engine v1

Чтобы не улететь в космос, v1 должен быть простым.

Query Engine v1 умеет:
1.

определять район из текста

2.

определять категорию

3.

определять услугу

4.

определять intent:

category browse

object search

service search

district search

event search

5.

строить простой структурный запрос

18. Пример минимальной таблицы смыслов

Можно мыслить так:

"бокс" → SERVICE_BOXING_TRAINING
"тренер" → PERSON / coach
"махмутлар" → DISTRICT_MAHMUTLAR
"аптека сегодня" → EVENT_PHARMACY_DUTY + today

Это уже даст много пользы без тяжёлого AI.

20. Чего нельзя делать
Нельзя

сразу строить “умный AI”, если нет query engine.

Нельзя

путать substring search и city query.

Нельзя

отдавать AI грязые данные напрямую.

Нельзя

строить гео-навигацию, если район не стал объектом.

23. Фиксация

CITY QUERY RULE v1
AliMind отвечает пользователю не прямым поиском по строкам, а через интерпретацию запроса и выполнение структурного городского запроса.

User Query → Intent + Entities → Graph/Data Query → Result

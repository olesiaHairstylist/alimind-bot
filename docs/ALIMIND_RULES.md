# AliMind — Инженерные правила проекта

Этот документ фиксирует основные правила разработки и развития системы AliMind.

Правила нужны для того, чтобы система оставалась устойчивой и не превращалась в хаос.

---

# 1. Система работает на данных

AliMind — это система обработки данных города.

Источники → данные → обработка → бот → пользователь.

Бот не является источником информации.

---

# 2. Только открытые источники

Система использует только:

* официальные сайты
* открытые сайты
* публичные данные

AliMind не создаёт данные.

---

# 3. Один источник — один парсер

Каждый источник должен иметь отдельный модуль.

Пример:

pharmacies_source.py
water_source.py
electric_source.py

Это позволяет быстро исправлять ошибки.

---

# 4. Парсер не должен ломать систему

Если источник изменился:

система должна продолжать работать
используя последний snapshot.

---

# 5. Бот не обращается к сайтам напрямую

Telegram-бот работает только с сохранёнными данными.

Сайты читают только парсеры.

---

# 6. Любые данные проходят проверку

Перед публикацией данные должны быть проверены.

Проверяется:

* наличие данных
* количество записей
* корректность структуры

Если данные выглядят подозрительно — они не публикуются.

---

# 7. При отсутствии данных система честна

Если данных нет:

бот пишет

"Нет данных".

Система не делает предположений.

---

# 8. Простота интерфейса

Бот должен отвечать:

коротко
понятно
без лишнего текста.

---

# 9. Пилотный город

AliMind строится с возможностью масштабирования.

Но текущий пилотный город:

Алания.

---

# 10. Польза важнее функций

Новая функция добавляется только если она делает систему полезнее в повседневной жизни.

AliMind — это ежедневный городской помощник.
